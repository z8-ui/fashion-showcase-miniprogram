# 服装图片展示小程序

2026-08 按甲方新需求重构：**逛专区组别 → 查看商品(图/视频) → 保存商品原图 → 微信发给商家**。
无购物车 / 无订单 / 无在线支付（个人主体可发布）。

## 核心流程

```
用户: 首页四专区 → 专区组别小卡片 → 组内商品列表(图/视频混排)
     → 详情查看 → 保存商品原图(无附加信息) → 保存相册 → 微信发给商家
商家: 首页底部"商家管理入口"(密码) → 选专区+组别+名称
     → 上传图片/视频 → 保存(持久化, 仅商家可删)
```

## 专区与组别结构（甲方指定）

| 专区 | 组别 |
|------|------|
| 男童裤子专区 | 宝宝组 / 小童组 / 中童组 / 大童组 / 青少年组 |
| 女童裤子专区 | 宝宝组 / 小童组 / 中童组 / 大童组 |
| 男童上衣专区 | 小童组 / 中童组 / 大童组 / 外套组 |
| 女童上衣专区 | 小童组 / 中童组 / 大童组 / 外套组 |

**小分组（第三级，可选）**：部分组别下可再分小分组，配置在 `utils/config.js` 的 `ZONES[].subGroups`。
当前仅「男童裤子专区 → 青少年组」配置了小分组：

| 组别 | 小分组 |
|------|--------|
| 青少年组（男童裤子） | 牛仔裤 / 休闲裤 / 工装裤 |

点进专区才显示组别小卡片，点组别进入该组商品列表（顶部可横向切换组别）；
组别下有小分组时，再显示小分组筛选条（默认"全部"，可点小分组只看该分组商品）。

## 商品数据模型（重要）

```js
{
  id: 'p123',          // 唯一ID
  name: '男童纯棉短袖T恤',
  gender: 'boy',       // boy男童 | girl女童
  part: 'top',         // top上衣 | pants裤子
  group: '小童组',     // 组别(见上表, 甲方指定)
  subGroup: '',        // 小分组(可选, 仅配置了 subGroups 的组别需要, 如 牛仔裤)
  media: [             // 1-3个, 图片/视频可混传
    { type: 'image', url: '...' },
    { type: 'video', url: '...', poster: '封面图...' }
  ]
}
```

## 持久化保证（图片/视频不丢失）

- **测试号阶段**：图片/视频拷贝到应用私有持久目录
  （wx.env.USER_DATA_PATH，微信不主动清理），元数据存本地存储。
  只有商家在管理页删除才会移除。
- **云开发阶段**（对接甲方真实 AppID 后）：上传到云存储，
  云端持久保存，只有甲方删除才移除。
- 上传/删除全部在手机上完成（wx.chooseMedia 支持拍照/相册/视频）。

## 商家管理入口（密码保护）

- 入口：首页底部「商家管理入口」
- 首次进入需**设置管理密码**（≥4位），之后每次进入需输入密码
- 管理页可「修改管理密码」，可上传/删除商品
- 测试号阶段用密码限制（无真实 openid）；对接甲方真实 AppID 后
  升级为**甲方微信 openid 白名单**验证（届时可去掉或保留密码双保险）

## 快速开始

1. 微信开发者工具「导入项目」→ 选择 `miniprogram/` 文件夹
2. AppID 选「测试号」（演示阶段；对接甲方账号后换真实 AppID）
3. 编译运行：首页 → 专区 → 组别 → 商品 → 保存商品图

## 测试号阶段限制（重要）

商家上传的图片/视频保存在**本机持久目录**，仅当前设备可见 ——
测试号阶段是"单机演示"，上传和查看需在同一设备。
对接甲方真实 AppID 后，将数据源切换为云开发（云存储+云数据库），
所有用户手机实时可见。切换只改 `services/api.js` + `utils/config.js`，
页面代码零改动（api.js 是统一出口）。

## 商家上传规范

- 商品图/视频 1-3 个，图片需包含价格/款号（甲方要求，前端不再显示这些字段）
- 图片按**原图上传**（不压缩，保证清晰）；视频 ≤60秒（内存保护）
- 必须选专区+组别，商品归入对应组别
- 管理入口需密码（甲方管理账号使用）
- 已上传列表支持**按商品名称检索**，检索后可删除（删除需确认，媒体文件一并移除）
